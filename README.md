# zkLeash

An LLM trading agent that cannot move funds unless an SP1 guest proves an EWMA risk check over a Pyth price history, and an ERC-7579 executor plus a loss ledger agree.

This is a final-year research prototype. It runs on Anvil and on testnets with mock tokens. It is not a trading system for real money.

## Layout

| Path | What it is |
| --- | --- |
| `prover/leash-risk` | Fixed-point risk function. Same code the guest runs. |
| `prover/cli` | Native host: `leash-risk scenario` and `leash-risk check`. |
| `prover/program` | SP1 entrypoint. Not built in CI; `make sp1-cycles` builds it. |
| `prover/exec` | Runs the guest ELF in the SP1 executor (no proof) and checks it against native `evaluate`. |
| `contracts` | Account, validator, executor, price log, ledger, tests. |
| `agent` | Tool-calling agent. Scripted by default. Ollama and Gemini optional. |
| `services` | Orchestrator, price-log cron, demo market maker. |
| `bench` | Randomized harness, gas samples, figures. Results in `bench/results`. |
| `dashboard` | Next.js view of the orchestrator. |
| `docs` | Threat model, ABI, risk math, synopsis, report, viva, demo. |
| `paper` | Review of the paper, the script that builds `zkLeash_IEEE_paper_v3.docx`, and the submission checklist. |

## Tests

```bash
make test
```

That needs Rust, Foundry, and Python 3.12. `make test` creates `.venv` if it is missing.

Pieces:

```bash
cd prover && cargo test -p leash-risk
cd contracts && forge test
PYTHONPATH=agent .venv/bin/pytest -q agent/tests prover/reference
.venv/bin/python bench/leashbench.py
```

Paper numbers and figures:

```bash
make gas        # bench/results/gas.json
make figures    # bench/results/salami_curve.png, paper/figures/architecture.png
make sp1-cycles # needs the SP1 v6 toolchain; bench/results/sp1_cycles.json
make paper      # zkLeash_IEEE_paper_v3.docx from the results files
```

## Local chain

```bash
bash script/e2e_anvil.sh
```

This deploys mock tokens, a mock Pyth, and the mock verifier. The mock verifier does not check proofs. Security tests use `SP1HonestVerifier` inside Foundry instead.

## Orchestrator and dashboard

```bash
.venv/bin/python services/orchestrator.py
cd dashboard && npm install && npm run dev
```

The dashboard talks to `http://127.0.0.1:8000`.

## Proofs on a laptop

Daily work runs the guest logic natively (`leash-risk scenario`, `leash-risk check`), which does not prove it. `make sp1-cycles` runs the compiled guest in the SP1 executor, also without a proof, and checks that its public values match the native run byte for byte. `SP1MockVerifier` is for wiring a deployment. `prover/script/prove.sh` is the Groth16 path, and it expects the Succinct Prover Network. The email asking for academic credits is `docs/outreach/succinct-academic-credits.md`.

## What is not in this tree

The Anvil deploy uses mock tokens and `SP1MockVerifier`. Foundry security tests use `SP1HonestVerifier`, which checks a commitment of the public values, not a Groth16 proof. There is no Base Sepolia deployment and no Prover Network proof in the results. `bench/heldout.json` repeats the same scripted families; it is not an independent held-out set. The paper is `zkLeash_IEEE_paper_v3.docx`, generated by `make paper` from the results files. `paper/REVIEW.md` explains the earlier review. `paper/main.tex` is an older draft. `paper/SUBMISSION.md` is the checklist for posting it. Nothing has been uploaded to arXiv.

A Base mainnet fork needs your own RPC:

```bash
anvil --fork-url "$BASE_RPC" --fork-block-number "$BASE_BLOCK"
```

Point `PYTH_ADDRESS` and the price ids in `.env.example` at the real feeds before that script is useful. `script/e2e_anvil.sh` is the path that was actually run.
